## Tracker implementation and migration

### Ownership and scope

Codex is the sole automated writer. Claude reads both workbooks for duplicate and bank/group checks. Gmail provides evidence of sends and replies. These are setup requirements; the separate outreach workbook has not yet been created or populated.

### Separate outreach workbook

Create `Outreach Tracker.xlsx` in this folder before activating outreach. Use expanding tables rather than fixed row limits.

- `Prospects`: stable Contact ID, name, email and aliases, LinkedIn URL, parent bank, firm, group, office, title, connection evidence, profile-check date, email source/verification, handoff ID, status, initial-send date, reply date/type/evidence, next action, reminder date, suppression reason, group-sequence closure/cooldown, main-tracker link, and promotion status.
- `Outreach Log`: unique Event ID, Contact ID, event timestamp, event type (`Initial Email`, `Manual Follow-Up`, `Human Reply`, `Auto Reply`, `Bounce`, `Opt Out`), Gmail message/thread IDs, sender address, résumé version, and factual notes.

Keep unsent accepted prospects here as `Target`; only confirmed Gmail sends become `Reached Out`. Keep unanswered prospects and their reminders out of the main tracker. Preserve the outreach record after a reply; promotion is a copy/upsert, not a deletion. Count daily initial sends using unique Gmail message IDs, not contact rows or copies of events in another workbook.

### Main recruiting workbook

`Recruiting Tracker.xlsx` remains authoritative for applications and established networking contacts. The response-only rule applies to its `Connections & Networking` and `Networking Chats` sheets, not application sheets.

Add a person only when a genuine human reply/reach-back is evidenced by Gmail, another verified channel, or {OWNER_NAME}'s explicit report. An out-of-office notice, delivery receipt, bounce, email open, or connection acceptance without a message does not qualify. A human decline still qualifies as a reply, but record `Declined`/`Do Not Contact` accurately rather than implying an active relationship. A named referral does not establish that the referred person has replied.

Upsert by existing email/aliases and LinkedIn identity; preserve existing Notes and row order. Store the stable outreach Contact ID in a dedicated linkage field added during setup, not in user-owned Notes. Log the reply and, if useful, the original initial-email event once with its original date/message ID. Subsequent calls, notes, and relationship reminders belong in the main workbook. Retain outreach send/reply evidence for reconciliation and reporting.

### Cross-workbook safety

Before every initial email, check both workbooks and Gmail for prior sends, existing relationships, suppression, and active bank/group threads across offices. Never treat absence from the main tracker as permission to email.

Under one exclusive writer lock, save confirmed reply evidence to the outreach tracker, upsert the main contact and reply interaction, verify both writes, then mark promotion complete. If interrupted, leave promotion pending and retry idempotently using Contact ID and Gmail message ID. Never resend an email to repair a tracker error. Reconcile unresolved sends from prior dates, not just today, before new outreach.

### Existing-record migration

Do not delete or move existing main-tracker records based only on a `Reached Out` label or missing reply date. First back up the workbook and verify Gmail/history or {OWNER_NAME}'s account. Copy proven unanswered outreach and associated events into the separate workbook and verify row counts, notes, and message IDs before removing only those verified cold-only entries from the main networking sheets. Hold ambiguous records for review; never alter application sheets. No migration has been performed yet.
