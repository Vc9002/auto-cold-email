# Codex instructions: outreach and tracker management

Read `NETWORKING_CONTEXT.md` together with this document. This pair is the complete instruction packet for a daily run.

## Role and schedule

Codex consumes `Networking Handoffs/research_pool.json`, verifies candidates, sends **initial** networking emails, and owns writes to both `Trackers/Outreach Tracker.xlsx` and `Trackers/Recruiting Tracker.xlsx`. Cold outreach belongs only in the separate outreach workbook; the main workbook's networking sheets receive a person only after a genuine human reply.

**One invocation per send day**, Monday–Thursday, at **10:00 a.m. Eastern**, sending up to **10 initial emails**, for a maximum of **40 per week**. Friday–Sunday: no initial sends. There is no per-city window and no shared-lock coordination between windows — a single run does the whole day's batch, which removes the three-way lock/reservation logic entirely. (A New York-timed 10am send reaching an SF banker at 7am their time is fine; nothing in this campaign requires local-morning delivery.)

## Steps for each run

1. **Reconcile prior work first.** Before touching the pool file, reconcile all unresolved confirmed Gmail sends from prior dates into the outreach tracker, and reconcile any pending responder promotions into the main tracker. If either tracker is unavailable or in a conflicting Excel/cloud-sync state, send zero new messages and report what needs reconciliation.
2. **Read and validate the pool file.** Run `python "Networking Workflow/outreach_preflight.py" --validate-pool`; if it does not print `PASS`, send nothing and report the reason. (The script's older default mode validates the retired dated-handoff files and will always block now; use `--validate-pool`.) Then open `Networking Handoffs/research_pool.json`. Filter to `status: "READY"`, sort by `priority_rank` ascending. This is now the single source of candidates — there is no dated handoff file to select between and no freshness/staleness check on a filename, since the pool is continuously updated. Take candidates in rank order until you have enough validated ones to fill today's remaining capacity (10 minus today's already-confirmed sends via Gmail message ID).
3. **Revalidate each selected candidate.** Read the current 40-firm list in `NETWORKING_CONTEXT.md`, the candidate's row in the pool file, the contact row and interaction history in both trackers, and Gmail Sent. Open the linked profile only when a role, office, group, or connection appears to have changed since `profile_checked_at_et`. Reject: a prior initial send to that person, opt-out, bounce, unresolved duplicate, non-IB role, unverifiable current office, or an active cold-outreach thread in the same parent bank and IB group across cities/brands. After an unanswered sequence ends, wait at least 21 days before another person in that bank/group, unless there is a real warm introduction.
4. **Confirm the email is usable.** Require `email_verification_state` of `verified` or `accept_all_2plus_agree` from the pool file. Never construct, guess, or independently hunt for an address — if the pool file doesn't already have a usable one for this person, skip them and take the next-ranked candidate. Recheck the address against Gmail Sent and both trackers for conflicts.
5. **Prepare the email and résumé.** Use the candidate's `specific_reason` from the pool file, and ask for a 15–20 minute phone/video conversation. Do not ask for a referral or job in the first message. End with `Best,`; Gmail supplies the signature. Use the one canonical résumé source configured for this campaign; if the canonical source has not been set, cannot be read, or conflicts with another purported current version, stop before sending. Confirm Gmail's actual `From` address is {OWNER_NAME}'s Penn school email.
6. **Send.** Confirm recipient, company email, subject/body, and attachment before each send. Count unique confirmed initial sends today via Gmail message IDs reconciled with tracker interactions; stop at 10 total. If fewer candidates qualify, report the actual shortfall — never make up volume or move a missing quota to another day.
7. **Reconcile each send.** Confirm the message and attached résumé in Gmail Sent. Update the outreach `Prospects` row to `Reached Out` (Last Touch, Next Action, seven-day reminder). Add an `Initial Email` event to `Outreach Log` with Gmail message ID, sender address, résumé version. Do not touch the main tracker for unanswered outreach.
8. **Write the send result back into the pool file.** For each person actually sent to, set their pool-file row to `status: "SENT"`, set `priority_rank` to null, and add `sent_at_et` and `gmail_message_id`. Re-read the pool immediately before writing and apply only these changes onto the fresh copy, so a research run that wrote in the meantime is not overwritten; run `--validate-pool` on the result. This is what lets Claude's next research run skip them without re-reading the trackers.
9. **Write a small duplicate-check digest for Claude, not the full tracker.** After step 8, write `Networking Handoffs/tracker_digest.json` containing just: every email address and LinkedIn URL with any send/reply history, and every parent-bank+group with an active or cooling-down thread (with the cooldown-until date). This is the only tracker-derived file Claude needs to read daily; it should be well under 5KB versus the 190KB+ full workbook. Overwrite it each run — it is a derived cache, not a record of truth.
10. **Close the run.** Report candidates considered, confirmed sends, skipped candidates and reasons, remaining weekly capacity, and any tracker/Gmail/pool-file discrepancy.

## Later relationship work

{OWNER_NAME} handles replies and arranges calls. At each run, check relevant inbound threads for human replies, or use {OWNER_NAME}'s explicit report of a response. On a confirmed human reply, mark the outreach record `Replied`, retain its history, and upsert that person into the main `Connections & Networking` sheet, with dated interactions in `Networking Chats`. A decline or opt-out counts as a human reply but must be marked accurately and suppressed where applicable. Automated replies, out-of-office notices, bounces, and delivery receipts stay in the outreach tracker only.

Prepare a short profile summary and three to five tailored questions before a call. After {OWNER_NAME} provides call notes, record them in the main tracker as `Chat`, preserve his notes verbatim, note referrals and agreed next steps, and remind him to send a thank-you within 24 hours.

## Tracker rules (unchanged)

Upsert by email/LinkedIn identity; preserve existing notes and row order. Never resend an email to repair a tracker error.
